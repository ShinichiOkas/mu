# 設計書: 死に筋商品抽出処理

## 1. 構造

### 1.1 ファイル構成
- `main.py` (または相当するスクリプト): 全体の制御、データ集計、レポート出力を行う。

### 1.2 データの流れ
1. **読み込み**: 
   - `inventory.csv` から商品マスター（コード、名称）を読み込む。
   - `sales.csv` から全販売履歴を読み込む。
   - `returns.csv` から全返品履歴を読み込む。
2. **集計**:
   - 商品コードをキーとしたハッシュマップ（辞書型）を作成し、商品ごとに以下の値を集計する。
     - `total_sales`: `sales.csv` における数量の合計
     - `total_returns`: `returns.csv` における数量の合計
3. **計算**:
   - `純販売数 = total_sales - total_returns` を算出する。
4. **抽出**:
   - `inventory.csv` に存在する商品かつ `純販売数 <= 0` であるものを抽出する。
5. **出力**:
   - 抽出結果を `dead_stock_report.txt` に書き出す。

### 1.3 責務の分割
- **データ読込層**: CSVファイルをパースし、リスト形式でデータを返す。
- **ロジック層**: 純販売数の計算および死に筋判定を行う。
- **レポート出力層**: 指定のフォーマットに従い、テキストファイルへ出力する。

---

## 2. 品質特性と実現構造

### 2.1 検証可能性 (Testability)
実装後の検証において、単にファイルの存在を確認するだけでなく、計算根拠が正しく出力されているかを確認する。
- **セルフテストの要件**:
  - 処理完了後、標準出力に以下の形式で結果を印字すること。
  - `[TEST] Processed: {inventory_count} items, Dead stock found: {dead_stock_count} items. Result: OK/NG`
  - これにより、スクリプトが正常に全データを走査したことを保証する。

### 2.2 正確性 (Correctness)
- 返品数のみが存在し、売上が0の場合も正しく「純販売数 $\le 0$」として判定すること。
- `inventory.csv` に存在しない商品コードが `sales.csv` 等に含まれていても、報告書には含めない。

## 3. 設計規則

### 3.1 一般規則
- **入力ファイルは読み取り専用**: `inventory.csv`, `sales.csv`, `returns.csv` を上書き、編集、削除してはならない。
- **成果物の制限**: 仕様で指定された `dead_stock_report.txt` のみを作成し、一時ファイル（.tmp, .log 等）をディレクトリに残さない。

### 3.2 レポート出力形式 (`dead_stock_report.txt`)
以下のフォーマットで出力すること。

**【ヘッダー】**
`死に筋商品報告書`

**【商品詳細（1商品1ブロック）】**
```
商品コード: [商品コード]
商品名: [商品名]
判定根拠: 売上[XX]個 - 返品[YY]個 = 純販売数[ZZ]個
--------------------------------------------------
```
- `[XX]`, `[YY]`, `[ZZ]` はそれぞれ算出された数値を埋め込む。
- 根拠文字列に必ず「純販売数」というワードを含めること。

### 3.3 ASCII マーカー
- レポート内の区切り線は `--------------------------------------------------` (ハイフン62個) とする。
