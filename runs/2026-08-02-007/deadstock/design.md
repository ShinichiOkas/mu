# Architecture Design: Deadstock Analysis Tool

## 1. 構造 (Structure)

### 1.1 ファイル構成
- `main.ps1` (実装者が作成): 全体制御スクリプト。以下のフローを順に実行する。
  1. データの読み込み
  2. 集計処理
  3. 判定処理
  4. 報告書の書き出し

### 1.2 データフロー
1. **入力層**:
   - `inventory.csv` $\rightarrow$ 商品マスタとして全商品リストを保持。
   - `sales.csv` $\rightarrow$ 商品ごとの販売数量を集計。
   - `returns.csv` $\rightarrow$ 商品ごとの返品数量を集計。
2. **処理層 (計算ロジック)**:
   - **実質販売数の計算**:
     - 商品 $P$ について：`実質販売数 = (sales.csvにおけるPの数量合計) - (returns.csvにおけるPの数量合計)`
     - `sales.csv` に存在しない商品は販売数 $0$ とする。
     - `returns.csv` に存在しない商品は返品数 $0$ とする。
   - **死に筋商品の判定**:
     - `inventory.csv` に存在する全商品を走査し、以下のいずれかに該当する場合に「死に筋商品」とする。
       - `sales.csv` に一度も出現しない。
       - 計算された `実質販売数` が $0$ 以下である。
3. **出力層**:
   - `deadstock_report.txt` へ、判定された商品の「商品コード」「商品名」「判定根拠（実質販売数：X個）」を書き出す。

### 1.3 責務の分割
- **データ集計**: 各CSVを読み込み、商品コードをキーとしたハッシュテーブル（連想配列）に数量を蓄積する。
- **判定エンジン**: `inventory.csv` のリストをベースに、集計データと照合して死に筋条件を判定する。
- **レポート生成**: 判定結果をフォーマットに従いテキストファイルに書き出す。

## 2. 品質特性と実現構造

### 2.1 検証可能性 (Testability)
- **セルフテストの実装**:
  - 実装者は、正常系および異常系（例：sales.csvが空、returns.csvにのみ記載がある等）を検証するテストコードを同梱すること。
  - テスト実行時は、単なる `exit 0` ではなく、以下の形式で結果を標準出力に印字すること。
    - `[TEST_RESULT] Executed: X, Passed: Y, Failed: Z`
- **データ整合性の担保**:
  - 計算過程で負数になるケース（返品数 > 販売数）があるため、これを適切に「0以下」として判定に含める。

## 3. 設計規則 (Design Rules)

### 3.1 制約事項
- **入力ファイルは読み取り専用**: `inventory.csv`, `sales.csv`, `returns.csv` を上書き、編集、削除してはならない。
- **成果物の限定**: 仕様で定義された `deadstock_report.txt` のみを作成する。一時ファイルや作業用CSVをディレクトリに残してはならない。
- **文字コード**: 出力ファイル `deadstock_report.txt` は UTF-8 (BOMなし) で作成すること。

### 3.2 出力フォーマット規則
- 報告書内には必ず以下の文字列を含めること。
  - `実質販売数：[数値]個`
- 商品コードと商品名は `inventory.csv` の定義に従うこと。
