## 2. しかし R0 の「何もしなかった」は判断ではなかった

PjM が編んだプロセスは正しかった:

```
1. (implementer) checker.py : 検査スクリプトを作る
2. (implementer) measure.json: checker.py を走らせて現状を測る
3. (implementer) README.md  : 実装に合わせて更新する
4. (qa)          verdict.md : 独立検証
```

①② は完了し、③ で**決定論 check に落ちた**:

> The task to update README.md failed the deterministic check (checker.py output != 0).

そして rerun → 予算切れ → escalate。**README が無傷だったのは、発行ゲート（合意030/037）が
半端な成果物を共有空間に出さなかったから**である。床は効いた。だが「不要と判断した」のではない。

## 3. 根本原因 — **不感帯は責務文に入ったが、検査器には入らなかった**

mu が作った検査器（R3 の `measure_script.py`）の出力:

```json
{ "expected_roles": ["pdm","pjm","architect","implementer","qa"],
  "file_analysis": {},
  "missing_roles": ["pdm","pjm","architect","implementer","qa"] }
```

**5役割すべてを「欠落」と報告している**（役割は `roles/*/*.md` に在るのに `.py` を見ている）。
`file_analysis` は空。**検査器は壊れていた。**

そして mu は**壊れた検査器に従った**。責務文には「事実ならあいまいでも書き換えるな」
「詳細の不足は直すな」と書いたが、**検査器はそれを知らない**。素朴に不一致を数え、
常に非ゼロを返す。**量の側に不感帯が無ければ、責務文の不感帯は届かない。**

さらに、**誰も検査器を検算していない**。私は 036 で自分の物差しに
「未着手なら NG・参照解なら全 ok に割れること」を課した（[[dry-run-the-instrument-before-the-experiment]]）が、
**mu が作る検査器には同じ規律を課していなかった**。

## 4. 私の計器の穴 — 検査器と測定結果が毎周消えていた

責務文は「`measure.json` に前回の測定結果があり、検査器があるならそれで測り直せ」と書いている。
**だが probe は毎周クローンを作り直し、持ち越すのは README.md だけである。**

実際、mu は毎周ちがう名前で作り直していた: `checker.py`（R0）→ `verifier.py`（R1）→
`checker.py`（R2）→ `measure_script.py`（R3）。

つまり **走を跨ぐ記憶（不感帯のヒステリシス側）は、一度も試されていない**。
032 の接地の交絡と同型の、**私の側の穴**である。
