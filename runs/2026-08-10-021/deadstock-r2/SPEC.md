# SPEC — L5（PdM）が目的から定めた仕様
（L5 の生成物。定義・受入基準は仮定を含む。直接編集して直してよい）

## 目的（人間の入力・原文）
在庫表 inventory.csv・売上履歴 sales.csv・返品履歴 returns.csv から、死に筋商品を特定して報告書を作ってくれ。なぜ死に筋と判定したかも分かるようにして。

## 操作的定義
- **純販売数量**: sales.csvにおける特定商品コードの数量合計から、returns.csvにおける同商品コードの数量合計を差し引いた値（純販売数量 = 総販売数 - 総返品数）。
- **死に筋商品**: 純販売数量が0以下の商品、または在庫表（inventory.csv）に記載があるが純販売数量が1未満である商品。

## 受入基準
1. [ ] 報告書ファイル（deadstock_report.txt）が存在すること（検査: `Test-Path deadstock_report.txt` → 出力に「True」を含むこと）
2. [ ] 報告書に「死に筋商品一覧」という見出しが含まれていること（検査: `Get-Content deadstock_report.txt` → 出力に「死に筋商品一覧」を含むこと）
3. [ ] 報告書に各商品の判定根拠（純販売数量などの数値）が記載されていること（検査: `Get-Content deadstock_report.txt` → 出力に「純販売数量」を含むこと）

## 仕様
【目的】
在庫表、売上履歴、返品履歴を照合し、純販売数量に基づいて「死に筋商品」を特定した報告書を作成する。

【定義】
- 純販売数量：sales.csvの数量合計 － returns.csvの数量合計
- 死に筋商品：純販売数量が0以下の商品、または在庫表に存在するが純販売数量が1未満の商品

【入力データ】
- inventory.csv（商品コード,商品名,在庫数）
- sales.csv（日付,商品コード,数量）
- returns.csv（日付,商品コード,数量）

【成果物】
- ファイル名：deadstock_report.txt
- 内容：
    1. 「死に筋商品一覧」という見出しを付けること。
    2. 特定された死に筋商品の「商品コード」「商品名」を列挙すること。
    3. なぜ死に筋と判定したか（例：純販売数量がX個であったため）という根拠を明記すること。

【検証基準】
- deadstock_report.txt が出力されていること。
- ファイル内に『死に筋商品一覧』および『純販売数量』という文字列が含まれていること。
