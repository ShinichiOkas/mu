# SPEC — L5（PdM）が目的から定めた仕様
（L5 の生成物。定義・受入基準は仮定を含む。直接編集して直してよい）

## 目的（人間の入力・原文）
在庫表 inventory.csv・売上履歴 sales.csv・返品履歴 returns.csv から、死に筋商品を特定して報告書を作ってくれ。なぜ死に筋と判定したかも分かるようにして。

## 操作的定義
- **商品コードの一致**: 大文字と小文字を区別せずに同一のものとみなす（ケースインセンシティブ）。例：'P001' と 'p001' は同一商品として扱う。
- **正味販売数**: sales.csvにおける特定商品コードの数量合計から、returns.csvにおける同商品コードの数量合計を差し引いた値。計算時の商品コードの照合は「商品コードの一致」に従う。
- **死に筋商品**: 正味販売数が 0 個以下である商品。ただし、inventory.csvに存在する商品コードのみを対象とする。照合は「商品コードの一致」に従う。

## 受入基準
1. [ ] 報告書ファイル（deadstock_report.txt）が存在すること（検査: `Test-Path deadstock_report.txt` → 出力に「True」を含むこと）
2. [ ] 報告書に、死に筋と判定された商品の商品コードと商品名が含まれていること（検査: `Get-Content deadstock_report.txt`）
3. [ ] 報告書に、各商品の「正味販売数」が明記されており、判定根拠となっていること（検査: `Get-Content deadstock_report.txt`）

## 仕様
【目的】
提供された在庫、売上、返品のデータから死に筋商品を特定し、その根拠と共に報告書を作成する。

【定義】
1. 商品コードの一致：大文字と小文字を区別せずに照合する（Case-insensitive）。
2. 正味販売数 = (sales.csvの数量合計) - (returns.csvの数量合計)。照合は上記「商品コードの一致」に従う。
3. 死に筋商品 = inventory.csvに記載があり、かつ正味販売数が 0 個以下である商品。照合は上記「商品コードの一致」に従う。

【入力ファイル】
- inventory.csv (商品コード, 商品名, 在庫数)
- sales.csv (日付, 商品コード, 数量)
- returns.csv (日付, 商品コード, 数量)

【成果物】
- deadstock_report.txt

【報告書の構成要件】
- 特定された死に筋商品のリストを掲載すること。
- 各商品について、以下の項目を明記し、なぜ死に筋と判定したかの根拠を示すこと：
    - 商品コード
    - 商品名
    - 正味販売数（計算結果）
- 死に筋商品が一つも存在しなかった場合は、その旨を記載すること。
