## 2. なぜこうなったか — 責務が「存在検査」に潰れた

mu が自分で書いた `SPEC.md`（R0）の受入基準:

```
1. README.md が存在すること（検査: Test-Path README.md → 「True」を含む）
2. README.md に l0_chat.py 〜 l5_chat.py への言及があること（検査: 出力に「l0_chat.py」を含む）
3. README.md に L0〜L5 の階層構造が記述されていること（検査: 出力に「L5」を含む）
```

**「l0_chat.py」と「L5」を含む 26 行の文書は、この3基準を全部満たす。** 実際そうなった。
決定論 check も独立 QA も正しく働いた——**弱められた基準に対して**。

責務の原文は **∀ の主張**（README に書いてあることは*すべて*実装と合っていること）だが、
仕様は **∃ の検査**（*ある*記述が存在すること）に落ちた。これは 020 で research 領域で
観測・対処済みの「**∀→∃ の弱化**」とまったく同じ形である。

**そして今回 Director が選んだのは coding パッケージだった。**

| パッケージ | `pdm.md` の量化子保存規範（PRESERVE QUANTIFIERS） |
|---|---|
| research | **あり**（020 の実走観測から追加） |
| coding / rnd / secretary / book | **なし** |

020 の対処は research にしか入っていない。**同型の穴が4パッケージに残っていた**ことを、
この走が別ドメインの第2標本として露出させた。

## 4. L6 が埋めるべき落差（このスプリントの主成果）

> **責務は状態への約束（∀・継続）だが、L5 が受け取れるのは一回の目的（∃・単発）である。**
> 変換の瞬間に、(a) 継続が単発に潰れ (b) 全称が存在に弱まり (c) 「やらない」という選択肢が消える。

3つに分解すると、L6 が持つべきものが見える:

1. **「やらない」を第一級の結果にする。** いまの語彙は accept / respec / escalate で、
   どれも「やった上での判定」。**no-op が正常な帰結**である層が要る。
2. **責務と目的を別物として持つ。** 責務は保たれるべき述語であり、目的はその違反を
   埋めるための一回の作業。**目的を生成する前に「違反しているか」を判定する座**が要る
   ——L5 に渡すのは責務ではなく、**違反が観測されたときだけ生成された目的**であるべき。
3. **走を跨ぐ記憶が要る。** ただし三原則「状態・記憶の少なさ」と衝突する。
   今回の観測が示すのは「**前周に何をしたか**」だけでも往復は止まる、という最小要件。

**副次の学び**: 検証の床（決定論 check・独立 QA）は**仕様に対して**完璧に働いた。
壊れたのは仕様の側である。つまり L6 を足すだけでは足りず、**責務→仕様の変換に
量化子を保存させる規範**（既に research にはある）が同時に要る。

### 診断の測り直し — 規範は効いたが、止まらなかった

同じ R0（ドリフト無し・一致した状態）を規範追加後に再走した:

| | 規範なし（§1） | **規範あり** |
|---|---|---|
| mu が書いた受入基準 | 3件 | **7件**（層ファイルごとの per-item） |
| README の残存 | 891字（**96% 消失**） | **9,625字**（54% 消失） |
| 監査 NG（前 → 後） | 0件 → 3件 | 0件 → **5件** |
| 「何もしない」 | 不成立 | **不成立** |

**規範は形の上では効いた**——基準が1件から7件に割れ、量化が保たれた。破壊も半分以下に減った。
**しかし止まらなかった。** 理由は再走の SPEC を読めば分かる:

```
2. README.md が l0_chat.py の役割について言及していること（検査: 出力に「L0」を含むこと）
3. README.md が l1_chat.py の役割について言及していること（検査: 出力に「L1」を含むこと）
   …（7件とも同じ形）
```

**量化子は保たれたが、一件一件はいまだ「存在検査」である。** ここが本丸だった:

> **受入基準の語彙（`run` ＋ `expect` の部分文字列一致）は「存在」しか表現できない。**
> 「一致」を機械検査するには**両側を突き合わせる検査器**が要り、それは基準ではなく
> 成果物（実装者が書くプログラム）として要求しなければならない。

規範文に「'X exists' は EXISTENCE の検査であって AGREEMENT の検査ではない」と書いたが、
PdM は存在検査を書き続けた——**言葉で禁じても、表現できる語彙がそれしか無いなら回避できない**。
[[quantities-need-structure-not-prose]] と同じ形が、検査の種類について現れた。

### この節が L6 の落差に足すもの

§4 の3点に、4点目が加わる:

4. **∀ の責務には退化解がある**——「書いてあることが**すべて**正しい」を最も安く満たす方法は
   **何も書かないこと**。規範を強めるほど退化解が有利になる（基準7件を全部通すには、
   7件しか書かれていない文書が最適）。継続責務には「**いま満たしているものを壊さない**」という
   保存の制約が要るが、一回の目的にはその概念が無い。

## 7. 交絡の発覚と、階段による切り分け（フェーズ E）

### 師匠の問い

> そもそも README のあるべき姿の定義を渡した？ それがあれば退化解に至らないと思うのだが？

**渡していなかった。そして調べたら、mu は README を一度も見ていなかった。**

`_input_grounding()` は `max_files=12` で先頭12件に切る。クローンのファイルをソートすると
`README.md` は **18/24 番目**で、接地から落ちていた。**PdM は責任を負う当の文書を見ないまま
仕様を書いていた**（R0 のログでも、SPEC 作成前に README を読んだ形跡は無く、最初のツール実行は
`Test-Path README.md`）。§1〜§6 の結論はこの交絡を含む。

続けて師匠が構造を言い当てた:

> そもそも一致させ続けるというのはある種の制御ループなのだが、この制御ループの構造を
> 発明できていないのでは？ 発明させるべきか、スキルとして与えるべきか、そこを解かないとならない

そこで**議論ではなく測定で決めた**。接地 → 自力 → skill → 構造、と一段ずつ上る。

### 階段の結果（すべて R0＝ドリフト無し・一致した状態から）

| 走 | 与えたもの | README 21,108字 → | 監査（前→後） | 何もしないか | 作用の道具 |
|---|---|---|---|:---:|---|
| §1 R0 | 何も（交絡あり） | **891字** | 0→3 NG | ✗ | write_file |
| §6 R0 | 量化子の規範 | 9,625字 | 0→5 NG | ✗ | write_file |
| **E-1 R0** | **接地の修理** | 10,436字 | 0→5 NG | ✗ | write_file |
| **E-2 R0** | 接地＋**制御ループの skill 2件** | **29,668字** | 0→4 NG | ✗ | **edit_file を3回** |

### 分かったこと — 要素ごとに、解けた手段が違う

| 制御ループの要素 | 何で解けたか | 証拠 |
|---|---|---|
| **観測**（差分を測る） | **構造**（接地の修理） | 接地を直した途端、mu は**自力で** architect の分析タスク（`analysis.md` / `gap_analysis.md`）をプロセスに編んだ。受入基準も「存在すること」から「**内容が一致していること**」へ変わった |
| **作用を差分に留める** | **skill** | 「既存ファイルは `edit_file` で差分を当てる。`write_file` で作り直さない」を与えたら、`edit_file` が3回使われ、**破壊が止まった**（10,436字 → 29,668字） |
| **no-op**（差分ゼロなら何もしない） | **どちらでも解けなかった** | 接地を直しても skill を与えても、4走すべてで動いた。skill には「差分がゼロなら成果は変更なし」と明記したが効かない |

**no-op だけが残った理由ははっきりしている——結果契約に無い終端だからである。**
L5 が返せるのは accept / respec / escalate の3つで、そのどれも「やった上での判定」。
**契約に無い状態を skill は作れない。** 言葉で「何もしなくてよい」と言っても、
機構が「目的を受け取ったら仕様を作る」形をしている限り、通り道が無い。

### 破壊の機械的な原因（§4 の落差④を撤回する）

§4 で「∀ の責務には退化解がある（規範を強めるほど何も書かない方が有利）」と書いたが、
**これは誤診だった**。実体はもっと単純で、E-1 のログが示している:

```
[tool] write_file(..., content=# mu  > 与えられたゴールに向かって PDCA を回し…)
```

**21,108字の文書を1回の生成で作り直そうとして、10,436字で尽きた。** 退化解の選択でも
推論の失敗でもなく、**作用が「差分の適用」ではなく「全体の再生成」だったこと**による
物理的な喪失である。だから `edit_file` を指示しただけで止まった。

落差④は「**保守の作用は差分でなければならない。全体の再生成は、長い対象では必ず情報を失う**」
に置き換える。これは skill で解けた側なので、L6 の落差ではない。

### 残った L6 の落差（改訂版）

1. **no-op を第一級の結果にする**——契約に無い終端は skill では作れない（**実測で確定**）
2. **責務と目的を別物として持つ**——L5 に渡すべきは責務ではなく、**差分が観測されたときだけ
   生成された目的**。観測ステップ自体は mu が自力で編めることが分かったので、
   L6 が持つべきは「編ませるかどうかを決める座」である
3. **前周に何をしたかを覚える**——4走とも毎回ゼロから読み直した。ただし
   **エージェントの状態でなくてよい**——検査器と前回の測定結果を作業空間のファイルとして
   持てば、三原則「状態・記憶の少なさ」と衝突しない（L3 のファイル・グラウンディングと同じ流儀）
