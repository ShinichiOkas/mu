## 2. なぜこうなったか — 責務が「存在検査」に潰れた

mu が自分で書いた `SPEC.md`（R0）の受入基準:

```
1. README.md が存在すること（検査: Test-Path README.md → 「True」を含む）
2. README.md に l0_chat.py 〜 l5_chat.py への言及があること（検査: 出力に「l0_chat.py」を含む）
3. README.md に L0〜L5 の階層構造が記述されていること（検査: 出力に「L5」を含む）
```

**「l0_chat.py」と「L5」を含む 26 行の文書は、この3基準を全部満たす。** 実際そうなった。
決定論 check も独立 QA も正しく働いた——**弱められた基準に対して**。

責務の原文は **∀ の主張**（README に書いてあることは*すべて*実装と合っていること）だが、
仕様は **∃ の検査**（*ある*記述が存在すること）に落ちた。これは 020 で research 領域で
観測・対処済みの「**∀→∃ の弱化**」とまったく同じ形である。

**そして今回 Director が選んだのは coding パッケージだった。**

| パッケージ | `pdm.md` の量化子保存規範（PRESERVE QUANTIFIERS） |
|---|---|
| research | **あり**（020 の実走観測から追加） |
| coding / rnd / secretary / book | **なし** |

020 の対処は research にしか入っていない。**同型の穴が4パッケージに残っていた**ことを、
この走が別ドメインの第2標本として露出させた。

## 4. L6 が埋めるべき落差（このスプリントの主成果）

> **責務は状態への約束（∀・継続）だが、L5 が受け取れるのは一回の目的（∃・単発）である。**
> 変換の瞬間に、(a) 継続が単発に潰れ (b) 全称が存在に弱まり (c) 「やらない」という選択肢が消える。

3つに分解すると、L6 が持つべきものが見える:

1. **「やらない」を第一級の結果にする。** いまの語彙は accept / respec / escalate で、
   どれも「やった上での判定」。**no-op が正常な帰結**である層が要る。
2. **責務と目的を別物として持つ。** 責務は保たれるべき述語であり、目的はその違反を
   埋めるための一回の作業。**目的を生成する前に「違反しているか」を判定する座**が要る
   ——L5 に渡すのは責務ではなく、**違反が観測されたときだけ生成された目的**であるべき。
3. **走を跨ぐ記憶が要る。** ただし三原則「状態・記憶の少なさ」と衝突する。
   今回の観測が示すのは「**前周に何をしたか**」だけでも往復は止まる、という最小要件。

**副次の学び**: 検証の床（決定論 check・独立 QA）は**仕様に対して**完璧に働いた。
壊れたのは仕様の側である。つまり L6 を足すだけでは足りず、**責務→仕様の変換に
量化子を保存させる規範**（既に research にはある）が同時に要る。

## 5. この走が掘り当てた既存の欠陥2件（032 のスコープ外・要判断）

1. **coding / rnd / secretary / book の `pdm.md` に量化子保存の規範が無い**（上記）。
   research だけが 020 で対処済み。今回が第2標本なので、
   [[prompt-norms-are-countermeasures-not-generalities]] の「2つ目の実ドメインが出るまで
   一般化しない」条件は満たされた。
2. **`MU_ROLES_DIR=auto` のとき装備表示が全 skill を「効かない」と誤報する。**
   `show_skills(skills, paths, roles)` が**パッケージ選択の前**に `roles={}` で呼ばれるため、
   `unknown_targets` が全件を宛先不明と判定する。実際には選択後に正しく装着されている
   （表示だけの誤り）が、「構成と表示の一致を構造で保証する」（合意025）に反する。
   `l5_chat.py` / `probe_hard.py` / `probe_research.py` / `probe_standing.py` の4箇所。
