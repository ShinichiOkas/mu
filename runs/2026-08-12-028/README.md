- auto-schedule r1 のてこずりは選択層ではなく実行側で、しかも**ドメイン再現性のある
  壊れ方**（021 でも schedule は最難関）。当て推量試行 55回は「量・網羅性はテキスト規範

  から実行する」の手続きが無ければ、試行錯誤が正当化される。027 の一発達成との差分は
  PjM のプロセス設計（分析タスクの独立有無）に帰着した。

  （protect）はファイル不変を守るがサービス状態の副作用は守備範囲外——007 B2
  （新規ファイル作成は防がず観測）のサービス状態版。probe 側の構造対処（サービス状態
  diff の観測）は LONGTERM 候補。

  観測に接地した2走の調整で 021 以来の最難関課題が最速達成になった。
