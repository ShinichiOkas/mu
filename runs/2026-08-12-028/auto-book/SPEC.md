# SPEC — L5（PdM）が目的から定めた仕様
（L5 の生成物。定義・受入基準は仮定を含む。直接編集して直してよい）

## 目的（人間の入力・原文）
テーマ『修理』の掌編小説を書いてほしい。分量は800〜1200字。読者が結末で認識の反転（それまでの見え方が変わる驚き）を得られること。執筆と、編集者の指摘を受けた改稿を経た最終稿を story.md として納品すること。

## 操作的定義
- **分量**: story.md 内の本文の文字数（空白・改行を除く）が 800文字以上 1200文字以下であること。
- **認識の反転**: 物語の終盤で、それまで提示されていた状況、人物の属性、または物の正体に関する前提が覆され、読者が過去のシーンを別の意味で再解釈せざるを得なくなる構成であること。
- **改稿プロセス**: 初稿を執筆し、編集者役による改善指摘（プロットの矛盾、反転の弱さ、文章表現など）を少なくとも1回受け、それを反映させた修正を行う工程。

## 受入基準
1. [ ] 納品ファイル story.md が存在すること。（検査: `Test-Path story.md` → 出力に「True」を含むこと）
2. [ ] 本文の文字数が800字から1200字の範囲内であること。（検査: ` (Get-Content story.md -Raw).Replace("`r`n", "").Replace("`n", "").Replace(" ", "").Length`）
3. [ ] テーマである『修理』に関する記述が含まれていること。（検査: `Select-String -Path story.md -Pattern "修理"` → 出力に「修理」を含むこと）
4. [ ] 物語の結末において、読者の認識を反転させる仕掛けが盛り込まれていること。
5. [ ] 編集者の指摘に基づく改稿が行われた形跡（またはプロセス）を経て最終稿となっていること。

## 仕様
【目的】
テーマ『修理』に基づき、結末で読者の認識が反転する驚きのある掌編小説を執筆し、改稿を経て最終稿を納品する。

【定義】
- 分量：本文（空白・改行除く）が 800〜1200字であること。
- 認識の反転：物語の終盤で前提条件が覆り、読者が物語全体を再解釈すること。
- 改稿プロセス：執筆 → 編集者による指摘 → 修正 というサイクルを最低1回回すこと。

【成果物】
- ファイル名: story.md

【詳細要件】
1. 『修理』をテーマとした物語であること。
2. 構成として、中盤まで提示されていた状況が、結末の一撃で別の意味に変わる「認識の反転」を実装すること。
3. 以下のプロセスで作成すること：
   - ステップ1：初稿の執筆
   - ステップ2：編集者視点でのレビュー（反転の強度、文字数、文章の整合性の確認）
   - ステップ3：指摘を反映した修正
   - ステップ4：最終稿を story.md として保存

【検査基準】
- story.md が存在し、文字数が 800〜1200字であること。
- 文中に「修理」というキーワードが含まれていること。
- 結末に認識の反転があるか、および改稿プロセスを経ているかをQAが判定する。
