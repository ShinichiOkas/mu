## 主観測①: 規範が L3 の再計画で薄まる（機構の穴）

019-B の「FAIL を含む判定書も完成」は **L4 の task_goal（判定書契約）にだけ**入る。
L3 はその goal から**自分の言葉で unit を計画**し、L2 は **unit の criterion に対して**
合否を判定する——つまり契約と規範は **L3 の計画者の転記を通ったときだけ** L2 に届く。
今回は QA の L3 が混乱して再計画を繰り返し（11 unit の計画・file 空欄 unit・
expect『FAIL』の検査発明まで）、転記のたびに規範が欠落した。

**規範を確率的な転記に乗せている**——合意008 の「契約はコードが供給する」が、
層を1つ跨いだところで破れている。対策候補: QA タスクの契約（_VERDICT_CONTRACT ＋
完成条項）を task_goal だけでなく **task_system（役割 system）に載せる**。
system は L3→L2 へ**コードが素通しで運ぶ**ため、再計画で薄まらない。
