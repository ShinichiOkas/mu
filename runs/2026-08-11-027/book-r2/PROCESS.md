# PROCESS — L4（PjM）が編んだプロセス（体制表）
（PjM の生成物。役割・人選・順序は仮定を含む。直接編集して直してよい）

## 目的
テーマ『修理』の掌編小説を書いてほしい。分量は800〜1200字。読者が結末で認識の反転（それまでの見え方が変わる驚き）を得られること。執筆と、編集者の指摘を受けた改稿を経た最終稿を story.md として納品すること。

## タスク列
1. [x] **writer** → `story_draft.md`
   - task: テーマ『修理』に基づき、結末で読者の認識が反転する（どんでん返しがある）掌編小説の初稿を執筆してください。文字数は800〜1200文字（空白・改行除く）を目指してください。
   - 成功条件: テーマ『修理』が含まれ、認識の反転がある構成であること。分量が概ね800-1200文字であること。
2. [x] **editor** → `review_notes.md`
   - task: story_draft.md を読み、編集者の視点から「認識の反転」が十分に機能しているか、テーマ『修理』の描き方が効果的か、分量は適切かという観点で改善点を洗い出してください。
   - 成功条件: 具体的かつ建設的な修正指示が記載されていること。
3. [ ] **writer** → `story.md`
   - task: review_notes.md の指摘内容を反映させ、story_draft.md を修正して最終稿を作成してください。最終的に空白・改行を除いた文字数が 800文字以上 1200文字以下になるよう厳密に調整してください。
   - 成功条件: 指摘事項が解消され、文字数が 800文字以上 1200文字以下であること。
   - 検査: `(Get-Content story.md -Raw).Replace("\s", "").Length`
4. [ ] **qa**（model: qwen3.5:9b） → `verdict.md`
   - task: SPECに基づき、story.md が以下の条件を満たしているか検証してください：1. ファイルが存在すること。2. 文字数が800〜1200文字であること。3. テーマが『修理』であること。4. 結末で認識の反転が起きていること。
   - 成功条件: 全ての完了条件を満たしているか判断し、結果を記録すること。 / 判定書が受入基準の**全番号**について『ITEM <番号>: PASS|FAIL|UNCERTAIN — 根拠』を含む。**FAIL / UNCERTAIN を含む判定書も、全番号に根拠が書かれていれば完成である**（成果物の不備を直すのは QA の仕事ではない。不備の事実を書くことが仕事）
