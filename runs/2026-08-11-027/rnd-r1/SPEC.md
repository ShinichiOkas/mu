## 目的（人間の入力・原文）
Python でリストの先頭に要素を大量に挿入するとき、list.insert(0, x) と collections.deque の appendleft のどちらがどの程度速いかを、実験で決着させてくれ。仮説を立て、計測実験を設計・実施し、結果の数値に基づいて評価した報告書 report.md にまとめること。計測は再現可能なスクリプトとして残し、報告書に載せる数値はそのスクリプトの実出力と一致していること。

## 操作的定義
- **大量に挿入**: 要素数 100,000 件以上の挿入操作を行うこと。
- **速い**:  동일な操作回数において、スクリプトの実行時間（壁時計時間）が短いこと。
- **再現可能なスクリプト**: 外部入力なしに単独で実行可能であり、実行のたびに同様の傾向の計測結果を出力する Python ファイル (.py)。

## 仕様
Pythonにおけるリスト先頭への要素挿入パフォーマンスを検証し、report.md にまとめる。

### 1. 定義
- 大量に挿入: 100,000件以上の挿入操作を指す。
- 速い: 実行時間（秒）が短いことを指す。
- 再現可能なスクリプト: 同一環境で実行した際に、同様の計測結果が得られる独立した .py ファイル。

### 2. 要求事項
- **計測実験の設計と実施**:
    - `list.insert(0, x)` と `collections.deque.appendleft()` の2手法を比較する。
    - 挿入件数を変数化し、十分な量（10万件以上）で計測を行うこと。
    - `time` モジュール等を用い、純粋な挿入処理時間を計測すること。
- **成果物の作成**:
    - `benchmark.py` (名称任意): 実験を再現するためのスクリプト。実行すると各手法の所要時間を標準出力すること。
    - `report.md`: 以下の構成を含む報告書。
        - 仮説: 実験前にどちらが速いと予想したか、およびその理由。
        - 実験設計: 使用したPythonバージョン、挿入件数、計測方法。
        - 結果: `benchmark.py` の実行結果（数値）をそのまま転記。
        - 評価: 数値に基づき、どちらがどの程度速いかを結論付ける。

### 3. 検査基準
- `benchmark.py` および `report.md` が作成されていること。
- `report.md` 内に「仮説」「評価」のセクションが存在すること。
- `report.md` 内に `insert` および `appendleft` の計測数値が明記されていること。
- `report.md` の数値が `benchmark.py` の実出力と一致していること。
