# SPEC — L5（PdM）が目的から定めた仕様
（L5 の生成物。定義・受入基準は仮定を含む。直接編集して直してよい）

## 目的（人間の入力・原文）
テーマ『修理』の掌編小説を書いてほしい。分量は800〜1200字。読者が結末で認識の反転（それまでの見え方が変わる驚き）を得られること。執筆と、編集者の指摘を受けた改稿を経た最終稿を story.md として納品すること。

## 操作的定義
- **掌編小説**: 単一の完結した物語を持つ短編小説。本件では文字数制約により、起承転結を極めて簡潔に構成した形式を指す。
- **認識の反転**: 物語の結末（ラストシーン）において、それまで読者が前提としていた状況、人物設定、または物の正体が、提示された新事実によって180度異なる意味に書き換えられる構成。
- **分量（800〜1200字）**: PowerShellの '(Get-Content story.md -Raw).Length' コマンドによって算出される数値（文字列の長さ）が、800以上 1200以下であること。

## 受入基準
1. [ ] 納品ファイル story.md が存在すること（検査: `Test-Path story.md` → 出力に「True」を含むこと）
2. [ ] story.md の文字数が 800文字以上 1200文字以下であること（検査: `$len = (Get-Content story.md -Raw).Length; if ($len -ge 800 -and $len -le 1200) { 'Pass' } else { "Fail: $len" }` → 出力に「Pass」を含むこと）
3. [ ] テーマである『修理』に関する記述が含まれていること（検査: `Select-String -Path story.md -Pattern "修理"` → 出力に「修理」を含むこと）
4. [ ] 結末において、読者の前提を覆す「認識の反転」が組み込まれていること
5. [ ] 編集者の指摘を受けた改稿プロセスを経た最終稿であること（履歴または修正跡の確認）

## 仕様
【目的】
テーマ『修理』に基づき、読者が結末で認識の反転（驚き）を得られる掌編小説を執筆し、改稿を経て最終稿を納品する。

【定義】
- 掌編小説: 単一の完結した物語。本文は空白・改行含め 800〜1200字とする。
- 認識の反転: 結末でそれまでの状況や設定が異なる意味に書き換えられる構成。
- 修理: 物語の主軸となるテーマ。
- 文字数判定: PowerShell の '(Get-Content story.md -Raw).Length' の戻り値を文字数として扱う。

【納品物】
- story.md (最終稿のテキストファイル)

【要件】
1. 内容: 『修理』をテーマにした物語であること。物語の終盤で、読者がそれまで抱いていた認識が覆される仕掛けを設けること。
2. 分量: story.md の本文が (Get-Content story.md -Raw).Length で測定して 800文字以上 1200文字以下であること。
3. 制作工程: 一度執筆した原稿に対し、編集者（または編集的視点を持つ第三者/AI）からの指摘を受け、それを反映させた改稿を行うこと。納品される story.md はその最終稿であること。

【検査基準】
- ファイル story.md が存在すること。
- (Get-Content story.md -Raw).Length の結果が 800〜1200 の範囲内であること。
- 文中に「修理」に関連する概念または単語が含まれていること。
- 結末に認識の反転があるか、QA担当者が内容を確認して判定する。
