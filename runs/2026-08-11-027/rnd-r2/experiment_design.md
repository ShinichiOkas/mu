# 実験設計書: `list.insert(0)` vs `collections.deque.appendleft` の性能比較

## 1. 問い
Python におけるリストの先頭への挿入（`list.insert(0, x)`）と、デックの先頭への挿入（`deque.appendleft(x)`）の間で、データ量が増加した際に実行時間にどのような差が生じるか。

## 2. 仮説の操作化
### 理論的背景
- **`list.insert(0, x)`**: Python の `list` は動的配列であり、先頭に要素を挿入すると、既存の全要素を一つずつ後ろにずらす必要がある。したがって、時間計算量は **$O(n)$** となる。
- **`collections.deque.appendleft(x)`**: `deque` は二方向キュー（双方向連結リストに近い構造）であり、先頭への挿入はポインタの操作のみで完結する。したがって、時間計算量は **$O(1)$** となる。

### 仮説
データ数 $n$ が増加するにつれて、`list.insert(0)` の実行時間は $n$ の増加に対して二次関数的（累積時間）または線形的（単一挿入）に増加し、`deque.appendleft` の実行時間はほぼ一定（単一挿入）または線形的（累積時間）に増加する。結果として、大規模なデータセットにおいて `deque` が圧倒的に高速である。

### 判定基準
- **支持**: $n = 10^6$ において、`deque.appendleft` の総実行時間が `list.insert(0)` よりも有意に（例：100倍以上）短い場合。
- **棄却**: 両者の実行時間に有意な差が見られない、あるいは `list` の方が高速な場合。

## 3. 実験設計
### 測定条件
- **挿入回数 ($n$)**: $10^4, 10^5, 10^6$ の3パターン。
- **計測項目**: 各 $n$ 回の挿入を完了するまでの総実行時間（秒）。
- **環境**: 同一の Python インタプリタ、同一のハードウェア環境で実行。
- **試行回数**: 各条件につき 3 回測定し、平均値または中央値を採用する。

### 手順
1. $n \in \{10^4, 10^5, 10^6\}$ について以下を繰り返す：
   - 空の `list` を用意し、`list.insert(0, i)` を $n$ 回繰り返し、その時間を計測する。
   - 空の `deque` を用意し、`deque.appendleft(i)` を $n$ 回繰り返し、その時間を計測する。
2. 計測結果をテーブル形式で記録する。

### 再現性の判定基準
- **結論の再現**: 異なる実行回において、数値自体は微変動しても、「$n$ が大きくなるほど `list` と `deque` の時間差が拡大する」という傾向が維持され、`deque` が常に高速であることで結論が再現されたと判定する。

## 4. 評価指標 (Metrics)
- **Total Execution Time (sec)**: $n$ 個の要素を挿入し終えるまでの正味の時間。
- **Time per Operation (sec/op)**: 総時間を $n$ で除した 1 回あたりの平均挿入時間。
