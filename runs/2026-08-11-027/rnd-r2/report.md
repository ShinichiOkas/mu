# 実験報告書: `list.insert(0)` vs `collections.deque.appendleft` の性能比較

## 1. 仮説
Python の `list` は動的配列であり、先頭への挿入 (`list.insert(0, x)`) は既存の全要素をシフトさせる必要があるため、時間計算量は $O(n)$ となる。一方、`collections.deque` は双方向連結リストに近い構造を持っており、先頭への挿入 (`appendleft`) はポインタ操作のみで完結するため、時間計算量は $O(1)$ となる。
したがって、挿入回数 $n$ が増加するにつれて、`deque.appendleft` は `list.insert(0)` よりも圧倒的に高速になり、その差は $n$ の増加に伴って拡大すると仮定した。

## 2. 実験設計
- **計測項目**: 指定回数の先頭挿入を完了するまでの総実行時間（秒）。
- **挿入回数 ($n$)**: $10^4, 10^5, 10^6$。
- **環境**: 
    - OS: Windows 11 10.0.26200
    - Python: 3.13.7 (tags/v3.13.7:bcee1c3, Aug 14 2025, 14:15:11) [MSC v.1944 64 bit (AMD64)]
    - Processor: AMD64 Family 23 Model 49 Stepping 0, AuthenticAMD

## 3. 結果
`benchmark.py` の実行により得られた実数値は以下の通りである。

| 挿入回数 ($n$) | `list.insert(0)` (秒) | `deque.appendleft` (秒) | 倍率 (Speed-up) |
| :--- | :--- | :--- | :--- |
| $10,000$ | $0.017557$ | $0.000456$ | 約 38.5 倍 |
| $100,000$ | $1.727691$ | $0.003451$ | 約 500.6 倍 |
| $1,000,000$ | Too slow ($O(n^2)$) | $0.034389$ | 計測不能 (圧倒的) |

## 4. 評価・結論
### 評価
- $n=10^4$ では `deque` が約 38.5 倍高速であった。
- $n=10^5$ では `deque` が約 500.6 倍高速になり、データ量が増えるにつれて速度差が劇的に拡大している。
- $n=10^6$ において `list.insert(0)` は時間的に実行不能（Too slow）となった一方で、`deque.appendleft` はわずか 0.034 秒で完了した。

### 結論
**`collections.deque.appendleft` は `list.insert(0)` よりも圧倒的に高速である。**
実験結果は、`list.insert(0)` が $O(n)$（累積 $O(n^2)$）、`deque.appendleft` が $O(1)$（累積 $O(n)$）であるという理論的な時間計算量の差を明確に裏付けており、当初の仮説は完全に支持された。
