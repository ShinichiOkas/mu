# 047 — gemma4 での依存解決。**解決器は決定性でも、系はモデル依存だった**（2026-08-16）

師匠の指示「今後の実験は gemma4:31b-cloud に戻す。デフォルトは gemma4、高性能モデルを試すときは glm」。
046（glm-5.2）と**同一条件**（責務文 v5・持ち越し・パッケージ固定・同じ題材・同じ監査）で、
モデルだけ替えた。

## 1. 決定的な差は**依存宣言の質**に出た

| | glm-5.2（046） | **gemma4（047・最終形）** |

同じドリフトを両方の宣言に当てた（決定性・LLM 不使用）:

| ドリフト | glm-5.2 | gemma4 |
|---|---|---|
| R1: skill を1件追加 | **検出**（`skills/verdict-cites-its-evidence.md が増えた`） | **見逃し** |
| R2: `probe_research.py` を削除 | **検出**（`probe_research.py が消えた`） | 初版は見逃し／最終形は検出 |

**`skills/` の欠落は最後まで直らなかった。**

## 2. 見逃しが live で再現した — **0秒で「満たされている」と宣言し、嘘を残す**

gemma4 の最終形の宣言で刻印を据え、R1（skill を1件追加）を走らせた:

```
R1: **何もしなかった** / achieved=True / 0s / README 変更: False
audit-after: 嘘 1件 ['skill の件数と宛先']  保存 100%
```

**系は「最新である」と正しく宣言し、README は間違ったまま残った。**
合意040 の「AI の懸念」に書いた静かな失敗（false negative）が、**既定モデルの初回で現実になった**。

> 宣言の漏れは静かな失敗になる。依存に書かれていない変更は永久に見逃される。
> 緩和は「宣言が1行で人間が読める」ことだが、**レビューされなければ効かない**。

## 3. 私の主張の訂正

046 の報告で私はこう書いた——「**決定性の部分はモデルに依存しません**」。
`mu/deps.py` については正しいが、**系全体については誤り**である。

> **解決器はモデル非依存。だが宣言を書くのは LLM なので、系はモデル依存である。**

gemma4 は解決器を1バイトも変えずに、**同じ機構で嘘を見逃した**。
「決定性の構造を入れたから確実になった」とは言えない——確実になったのは**解決**であって、
**宣言の網羅**は依然として判断であり、しかも**静かに外れる**。

## 5. 責務文 v5 は gemma4 には届かなかった

v5 は「陳腐化の判定はこちらが行う——あなたは測らなくてよい」と明記している。
glm はこれに従い、設計書に「陳腐化判定ロジックの実装禁止」と書いた。

**gemma4 は従わず、`verify_readme.ps1` と `verify_check.md` を作った**（R0 の成果物）。
[[verify-the-verifier-by-mutation]] の skill も同時に発火している。
**同じ文言が、モデルによって届いたり届かなかったりする**——知識は確率的にしか効かない、の実例。

## 6. 含意

1. **宣言の網羅を人間がレビューする経路が要る。** 「1行なので読める」は正しいが、
   誰も読まなければ意味がない。`DEPS.mk` を人間に見せる／承認する段が要る
2. **glob を使わせる方が安全**。列挙は「いま在るもの」しか捕まえず、**追加に構造的に弱い**
   （gemma4 は skills/ を列挙し忘れ、追加は永久に見逃す）
3. **既定モデルでは通し走が成立しない**（4周とも時間切れ）。締切の粒度（046 でも観測）と
   ブートストラップ問題が、gemma4 では同時に効く
