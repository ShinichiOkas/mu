### なぜか — 判断を単体で再現して読んだ

pristine なクローンに対して assess の判断だけを再現した（1判断）。答えは正直だった:

> The purpose is to keep README.md consistent with the current implementation. …
> **I cannot verify if the 47,715 bytes of README.md accurately reflect the current specific
> roles and interfaces of these layers without analyzing the full content of both the README
> and the implementation files.** Given the 'keep consistent' nature of the task and the
> likelihood of drift, **I must assume it is not fully satisfied.**

学習者に見えていたのは**接地の抜粋 2,073 字**（ファイル一覧＋各先頭5行）だけである。
47KB の文書と 3,500 行の実装の一致は、そこからは測れない。そして定義書に書いたとおり
「**迷ったら false**」——**規律に従った正しい false** である。

**つまり: 契約は入ったが、発火には「観測」が要る。**

## 3. この走が確定させたこと — **観測は判断ではなく仕事である**

032 の協議で師匠が言い当てた制御ループ（観測 → 差分 → 差分だけ作用 → 再観測）のうち、
034 が実装したのは**「差分ゼロなら止まる」という契約**だけだった。**観測**は入っていない。

- 小さな対象（数行のファイル）では、接地の抜粋がそのまま観測になる → 契約は発火する
- 大きな対象（47KB × 3,500行）では、**観測それ自体が道具を使う仕事**であり、
  1判断の射程を超える → 契約は正しく「分からないので進む」に落ちる

**責務の座**（合意033 C v2 で分離した将来の層）の設計に、これは直接効く:

> 観測は**タスク**（道具を使って差分を測り、結果をファイルに残す仕事）であって、
> **判断ではない**。責務の座が持つべきは「観測タスクを回してから、その結果に対して
> no-op を判定する」という順序である。

mu には既にその形がある——L2（ゴールを与えて道具で完遂させる）。観測を L2 の1走として
回し、その成果物（差分レポート）に対して assess を問えば、大きな対象でも測れるはずである。
**ただしコストは1走ぶん増える**——ここは設計判断として次スプリントに持ち越す。
