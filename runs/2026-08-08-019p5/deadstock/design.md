# 設計書: 死に筋商品分析レポート生成

## 1. 構造

### 1.1 ファイル構成
- `deadstock_analysis.ps1` (実装者が作成するメインスクリプト)
- `deadstock_report.txt` (出力成果物)

### 1.2 データの流れ
1. **データ読込**: `inventory.csv`, `sales.csv`, `returns.csv` を読み込む。
2. **集計**: 
    - `sales.csv` から商品コードごとの数量合計（総販売数）を算出。
    - `returns.csv` から商品コードごとの数量合計（総返品数）を算出。
    - 商品コードの表記揺れ（大文字・小文字）は統一して扱う。
3. **純販売数計算**: 
    - `純販売数 = 総販売数 - 総返品数` を計算。
4. **判定**: 
    - `純販売数 <= 0` の商品を「死に筋商品」として抽出。
5. **レポート出力**: 判定基準、該当商品、および根拠数値を `deadstock_report.txt` に書き出す。

### 1.3 責務の分割
- **集計ロジック**: CSVのパース、商品コードをキーとしたハッシュテーブルへの集計。
- **判定ロジック**: 定義されたしきい値（0以下）によるフィルタリング。
- **出力ロジック**: 指定フォーマットに従ったテキストファイルの生成。

## 2. 品質特性と実現構造

### 2.1 検証可能性 (Verifiability)
- **セルフテストの導入**: 実装スクリプトは、正常終了時に処理した商品数と抽出した死に筋商品数を標準出力に表示し、以下の ASCII マーカーを印字すること。
    - `[TEST_RESULT: SUCCESS]` (正常終了時)
    - `[TEST_RESULT: FAIL]` (エラー発生時)
- **計算根拠の明示**: レポートに「総販売数」「総返品数」「純販売数」をすべて記載し、人間が目視で再計算可能にすることで、ロジックの正当性を検証可能にする。

## 3. 設計規則

### 3.1 入出力規則
- **入力ファイルは読み取り専用**: `inventory.csv`, `returns.csv`, `sales.csv` を上書き・編集・削除してはならない。
- **成果物の限定**: 仕様で指定された `deadstock_report.txt` のみを作成する。一時ファイルを作成した場合は、処理終了前に必ず削除すること。

### 3.2 レポートフォーマット (`deadstock_report.txt`)
以下の構成で出力すること。
1. **判定基準**: 
   - 「純販売数（総販売数 - 総返品数）が 0 以下であること」という旨を明記。
2. **死に筋商品一覧**:
   - 商品コード、商品名の形式でリストアップ。
3. **判定根拠**:
   - 各商品について以下の形式で記載。
   - `商品コード: [コード], 販売数: [数値], 返品数: [数値], 純販売数: [数値]`

### 3.3 実装上の注意
- **大文字小文字の区別**: 商品コード（例: `P008` と `p008`）は同一の商品として集計すること。
- **欠損値の扱い**: 売上または返品にレコードが存在しない商品は、数量 0 として扱うこと。
