## 観測（噛み合わなかった点）

### ① 検査器が成果物になった（最重要）

人間が置いた検証スクリプト `check_sources.py`（出典 URL を叩いて `SOURCES_OK` を印字）を、
走行が **書き換えた**。経路は以下のとおりで、どの段階も「筋が通っている」のが厄介である。

1. **PdM は `check_sources.py` を受入基準に採用した**（環境に置いただけで拾った＝接地は働いた）。
   ただし期待マーカーを **`ALL_URLS_VALID` と発明**した——スクリプトが実際に印字する
   `SOURCES_OK` を**読まずに**決めた
2. **PjM はその食い違いを「実装課題」に変換した**。PROCESS.md タスク2 の指示:
   > Implement a accompanying check_sources.py script that parses URLs from report.md and
   > validates them via HTTP requests, outputting 'ALL_URLS_VALID' on success.
3. 実装者は指示どおり `check_sources.py` を**上書き**した。最初の版は
   **URL が 1 つも無ければ `ALL_URLS_VALID` を印字する**（空振り合格）実装だった

つまり **検証器を被検証者が作る**構図が成立した。コーディングでは検査＝「成果物に対してテストを走らせる」
であり、検査器の出所が問題になりにくい。リサーチでは検査器自体が小さなプログラムなので、
**成果物と検査器の境界が消える**。

> 007 で観測した「QA が成果物を直してしまう」の**リサーチ版**であり、より深い。
> あのときは成果物が汚染されたが、今回は**判定の土台**が汚染された。

なお `check_sources.py` は `tools.protect()` で保護していなかった（probe の設定漏れ）。
保護していれば書き換えは拒否され、食い違いは「検査が通らない」として表面化したはずである。

### ② 決定論 check は効いた（ただし偶然に助けられた）

L4 の最終検査は 3 件中 2 件 NG:

| 受入基準 | 結果 | 中身 |
|---|---|---|
| 4ツールの網羅 | ok | — |
| 出典 URL の検証 | **NG** | `python check_sources.py` が引数不足で exit=1（書き換え後の版は引数必須になっていた） |
| 結論の明記 | **NG** | 期待マーカーが日本語「結論」だったが、報告書は英語で `## Conclusion` |

**QA（LLM）は `ACHIEVED: yes` と判定していた**（verdict.md に「check_sources.py 実行結果:
`ALL_URLS_VALID`」と明記）。コード側の決定論 check がそれを止めた——
**判定を表象でなく実体に寄せる設計（合意005）は非コーディングでも効いた**。

ただし NG の理由は「出典が捏造されていた」ではなく**引数の食い違い**である。
守れたのは偶然に近い。①を塞がない限り、次は素通りしうる。

### ③ 期待マーカーが言語に依存した

「結論が明記されていること」の検査が `Get-Content report.md` → 期待文字列 **「結論」**。
報告書は英語で書かれ `## Conclusion` だったため NG。成果物がコードなら
マーカー（`12/12 passed` 等）は言語非依存だが、**文書は言語が揺れる**。
仕様（日本語）と成果物（英語）の言語不一致は、リサーチでは常態になりうる。

### ④ QA の権限が「検証の作業場」を持たない

権限拒否 33 回。QA は `write_scope: own`（`verdict.md` のみ書ける）ため、
`inspection_results.txt` / `temp_spec_check.txt` / `SPEC_analyzed.txt` などの
**中間検証メモを書こうとしては拒否され**、周を大量に浪費した。
コーディングの QA は「テストを実行して出力を見る」で完結するが、
文書の検証は**読んだ内容を書き出して突き合わせる**作業を伴う。
規律（成果物を書き換えない）は正しいが、**作業場が無い**のは設計の穴に見える。

### ⑤ 途中で主題が丸ごとドリフトした（そして自力で戻った）

中盤の `report.md` は **プロジェクト管理ツールの比較（Asana 等）** になっていた。
L2 Reflect と後続ラウンドで是正され、最終的に LLM 実行基盤の比較に戻った。
**部分再実行の機構は非コーディングでも働いた**が、
「主題が入れ替わる」失敗はコーディングでは見なかった型である。

### ⑥ probe 側の不具合（mu ではなくこちらの落ち度）

`probe_research.py` が最終結果（achieved / escalated / assessment）を
`_log(文字列)` で出そうとしていた。`_log` は**イベントタプル用**で、文字列を渡すと
`event[0]` が先頭 1 文字になり**どの分岐にも当たらず黙って捨てられる**。
このため**この走行の最終判定は記録に残っていない**（成果物とログからは、
受入基準 2 件 NG のまま L4/L5 の予算を使い切った、と読める）。
`print` に修正済み。次の走行からは記録される。

## 結論（この走行から言えること）

- **層構造そのものは非コーディングでも回った** — 目的→仕様→プロセス→役割→実行→QA→決定論 check の
  一巡は成立し、部分再実行も働き、最終成果物は妥当だった
- **壊れたのは「検査の独立性」** — 検査器を走行自身が書き換えられる状態だったこと（①）。
  ここが非コーディング領域で新たに露出した穴である
- **役割定義は差し替えが要る** — 特に QA の作業場（④）と、
  「実装者が検査器を実装する」への誘導（①の 2〜3 段目）
- **マーカーは言語非依存に** — 文書の検査に日本語マーカーを置くと言語不一致で落ちる（③）
