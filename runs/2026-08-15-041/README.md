# 041 抜き取り走（v3）— **R0 で文脈が尽きて中断**。ただし死因が答えの一部だった

師匠の指示「責務文の肥大がポジティブに効いていたかを確認しておこう」に対する
抜き取り走（[[knowledge-ablation-run-proves-the-knowledge]]）。責務文から
**「数えるものの限定」と「検算の要求」の143字だけ**を抜き（v4 556字 → v3 413字）、
それ以外（持ち越し・監査・条件・題材）はすべて 040 と同一で走らせた。

## 結果 — 完走しなかった

```
[L0:BadRequest] The prompt is too long: 262230, model maximum context length: 262144
```

R0 の implementer タスク（README 更新）の途中で死亡。**系列は取れていない。**

## 死因は v3 の性質そのものだった

mu が v3 で作った検査器は、こう出力する:

```
Mismatch: File chat_common.py: Role 'chat_common.py — CLI / probe が共有する実況・環境接地の共通部（層の外）。…'
Mismatch: File probe_learning.py: Role 'probe_learning.py — L6（学習の層）の中核能力＝診断を、…'
```

**docstring 全文を吐く散文の羅列**である。これが 41,028 バイトの README 書き込みと一緒に
会話へ積もり、10 周ぶんで 262k トークンを超えた。

040（v4）の検査器の出力はこうだった:

```json
{ "factual_errors": 11, "unmentioned_counts": 0 }
```

**2つの整数。**

| | v3（抜いた） | v4（入れた） |
|---|---|---|
| 検査器の出力 | 散文の羅列（docstring 全文） | 整数2つ |
| 走行 | **R0 で文脈超過・死亡** | 4周完走 |

**143字の指定は「何を数えるか」だけでなく、検査器の出力を『量』に縛っていた。**
不感帯は閾値を当てられる量の上にしか置けないので、これは偶然の副作用ではなく、
**指定の本質的な効果**である——散文を吐く検査器の上には、そもそも不感帯を設計できない。

## この走の位置づけ

- **肥大がポジティブに効いていたか** → **少なくとも1点で、明確に効いていた**（検査器の出力形式）
- ただし**完走していないので、系列（保存率・振動）の比較はできていない**。
  「143字が無くても安定するか」は未測定のまま
- 死因は環境（文脈上限）でもあるが、**そこへ至る経路は v3 が作った**。
  n=1 なので「v3 は必ず死ぬ」とは言えない

## 副次的に露出した弱点（スコープ外・要判断）

**文脈超過で走行が丸ごと死ぬ。** L0 は接続を理想化して4型のエラーを返すが、
`BadRequest`（文脈超過）は終端であり、部分結果すら残らない。
L1 のループは周回数（`L2_L1_MAX=10`）で縛られているが、**1周あたりの文脈量は縛られていない**
——41KB の書き込みを繰り返せば10周で上限に届く。合意018 ⑥ の内部締切と同じ思想の
「文脈の床」が無い。
