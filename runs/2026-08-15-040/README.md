# 040 実走記録 — 不感帯は量の側に入った。だが不動点は検査器が決める（2026-08-15）

合意 [039](../../.pair-agent/agreements/039-dead-band.md) フェーズ A'（責務文 v4 ＋ 持ち越しの修理）。
039 で開いていた3つの穴——(1) 検査器に不感帯が無い (2) 検査器が検算されない
(3) 検査器と測定結果が毎周消える——のうち、(1) と (3) を塞いで走らせた。

## 1. 結果

| 周 | 正解 | 所要 | 嘘（前→後） | 沈黙（前→後） | 保存 | 字数 |
|---|---|---|:---:|:---:|:---:|---|
| **R0** | 何もしない | 520s | 0→0 | 0→1 | 89% | 22,317 → 22,674 |
| R1 | 数の記述を直す | 453s | **1→0** | 1→4 | **24%** | → **3,876** |

4周とも `escalated=True`（予算切れ）。保護の破れ0・実装の変更0。

## 2. 塞がった穴 2つ

**(1) 不感帯が量の側に入った。** mu が作った検査器の出力は、責務文で指定した**2つだけ**になった:

```json
{ "factual_errors": 11, "unmentioned_counts": 0 }
```

039 の検査器（`missing_roles: [全5役割]` と誤報）とは別物である。あいまいさも詳細の不足も
数えていない。**責務文で「何を数えるか」を指定すれば、検査器はそのとおりに作られる。**

**(3) 持ち越しが効いた。** R1 以降、毎周 `[carry] 前周から持ち越し: README.md, measure.json,
verify_readme.py` が出ている。**走を跨ぐ記憶が初めて成立した**——mu は前周の検査器を
そのまま使い、測り直している。

## 3. 塞がらなかった穴 —— **検査器の定義域が間違っていた**

`verify_readme.py` の中身:

```python
impl_files = [f for f in os.listdir('mu/') if f.endswith('.py')]   # mu/ 直下だけ
mentioned  = re.findall(r'`([^`]+\.py)`', readme_text)             # README の `*.py` 全部
for mf in mentioned:
    if os.path.basename(mf) not in impl_files:
        factual_errors += 1
```

**「実装ファイル」を `mu/` 直下だけと定義したため**、ルート直下の実在ファイル
（`l5_chat.py`・`probe_hard.py`・`tools.py`・`chat_common.py` …）への言及が
**すべて「事実でない記述」に化けた**。これが `factual_errors: 11` の正体である。
私の監査は同じ README に対して**嘘 0件**——11件は全部**本当のこと**だった。

そして mu は**自分の検査器に従った**:

- **R1**: 検査器を満たすために、実在ファイルへの言及を削った。22,674 → **3,876字**（保存24%）。
  責務文には「前回まで述べていた正しい記述を落としてはならない」と書いてあるのに、
  **検査器の数字が規範に勝った**
- **R2/R3**: 削っても `factual_errors` は 0 にならない（`mu/` 外のファイルに触れる限り増える）。
  README タスクは毎回 `検査[NG]` で失敗し、rerun → 予算切れ。**発行ゲートが止めるので
  README は変わらない**

**R3 の「保存100%・完全無変更」は、不感帯が効いたのではない。到達不能な目標に対して
タスクが失敗し続け、床が半端な成果物を出さなかっただけである**（039 R0 と同じ形）。

## 4. この走が確定させたこと

> **不感帯は振動を止める。だが系がどこで止まるかは検査器が決める。**
> 検査器が間違っていれば、**安定して間違った場所に落ち着く**。

「安定」と「正しい」は別である。040 の系列（22,674 → 3,876 → 4,272 → 4,272）は
032 のような往復をしていない——**単調に落ちて、19% の定常点で静止した**。振動は消え、
不動点が残った。

問題は3走にわたって**同じ場所に移動し続けている**:

| 走 | 問題の在処 |
|---|---|
| 034 | 判断に**観測**が無い |
| 039 | 検査器はあるが**不感帯**が無い（＆ 5役割を誤報） |
| **040** | 不感帯は入ったが**定義域**が間違っている |

共通の根は**検算されない検査器**である。責務文 v4 には
「検査器を作ったら、いまの README.md で一度走らせ、あなたが直すべきと考える件数と
一致するかを確かめよ」と書いた。mu は走らせた（タスク2＝baseline 測定）が、
**11 という数字を疑わなかった**。

## 5. 次の一手（案）

**検算を成果物として要求する。** 032 §6 で得た形——「検査は基準ではなく成果物として
要求しなければならない」——を、**検査器そのものの検算**に適用する:

> 検査器が挙げた件数の**内訳を1件ずつ列挙し、それぞれ実物を確認した結果を
> `verify_check.md` に書け。**

11件を1行ずつ書き出せば、`l5_chat.py — 実在する` という行が並び、**矛盾が目に見える**。
言葉での指示（「確かめよ」）は素通りしたが、**列挙を成果物として要求すれば素通りできない**。

同時に、mu の `skills/` には「計器を疑う」規律が無い。ペア側には
[[extreme-measurement-suspect-the-instrument]] と [[dry-run-the-instrument-before-the-experiment]]
があるが、**mu には渡していない**。
