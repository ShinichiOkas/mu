# スプリント009 比較実走の記録（2026-08-05）

- **目的**: L4 を「進行の層（PjM）」と「目的の層（PdM）＝L5」に**分割した前後で挙動が変わっていないこと**の確認。
  分割は挙動を変えない改修なので、受入は「壊れていないこと」（合意009 未決4）。
- **構成**: 主力 gemma4:31b-cloud / QA 人選プール qwen3.5:cloud。予算は**各層が自分で持つ**形になった
  （L5_MAX=2 respec サイクル / L4_MAX=3 PjM サイクル。008 までは 1つの max_rounds=3 が両方を兼ねていた）。

## 結果 — 008 と同じ

| 走 | 009（2層） | 008（1層） | |
|---|---|---|---|
| contradiction（H3） | **escalated** / rounds=0・l4_rounds=0 / 1秒 | escalated / rounds=0 / 2秒 | ✅ 同じ |
| bugfix | **achieved** / rounds=1・l4_rounds=1 / 76秒 | achieved / 1 / 487秒 | ✅ 同じ |
| deadstock | **achieved**（P007・P010）/ rounds=1・l4_rounds=1 / 152秒 | achieved（P006/P007/P010）/ 1 / 181秒 | ✅ 同じ |

- 保護の破れは全走 none。
- H3 は **PdM が仕様を作らず即 escalate**（L4 は一度も起動していない＝`l4_rounds: 0`）。
  分割によって「どの層で止まったか」が返り値から直接読めるようになった。
- deadstock の答えは P007・P010。008 では P006（はさみ・実質9）も含んでいたが、これは
  死に筋の操作的定義の差（`<= 0` か `< 10` か）であり、SPEC.md にその定義が明記されている
  ——定義依存のケースがどちらに転んでも**根拠が artifact に残る**という 006 からの性質は維持。

## 副次的な観測

- **判定書の REASON が厚く返ってきた**（008 Phase4 で入れた「読み手を頑健に＋契約を成功条件に」の効果）。
  bugfix では QA が「テスト実行の出力／test_stats.py 未変更／SPEC が目的の制約を弱めていないこと／
  設計規則の遵守」の4点を根拠として列挙している。
- **所要が短縮**（bugfix 487→76秒、deadstock 181→152秒）。分割の効果とは断定できない
  （クラウド側のばらつきが大きい）が、劣化していないことは確認できた。

## 判定

**挙動は変わっていない。** 3走とも 008 と同じ結末で、保護の破れもなし。
層の分割は構造の整理であって、外から見た振る舞いを変えていない。
