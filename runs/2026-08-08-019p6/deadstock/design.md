# 設計書: 死に筋商品特定処理

## 1. 構造

### 1.1 ファイル構成
- `deadstock_report.txt` (出力)

### 1.2 データの流れ
1. **読み込み**: `inventory.csv`, `sales.csv`, `returns.csv` を読み込む。
2. **集計**: 
   - 商品コードごとに `sales.csv` の「数量」を合計し、販売合計数を算出する。
   - 商品コードごとに `returns.csv` の「数量」を合計し、返品合計数を算出する。
   - **重要**: 商品コードの比較はケースインセンシティブ（大文字小文字を区別しない）で行うこと（例: `p008` と `P008` は同一視する）。
3. **計算**: 
   - `純売上数量 = 販売合計数 - 返品合計数`
4. **フィルタリング**:
   - `inventory.csv` に存在する商品であり、かつ `純売上数量 <= 0` である商品を抽出する。
   - ※ `inventory.csv` に記載がないが `sales.csv` にのみ存在する商品は除外する。
5. **出力**: 抽出結果を `deadstock_report.txt` に書き出す。

### 1.3 責務の分割
- **データ集計モジュール**: CSVから商品ごとの数量を合算する。
- **判定モジュール**: 在庫リストと照合し、死に筋条件（純売上 <= 0）を判定する。
- **レポート出力モジュール**: 指定されたフォーマットでテキストファイルを出力する。

## 2. 品質特性と実現構造

### 2.1 検証可能性
- **計算の正当性**: 実装者は、計算過程（商品ごとの販売数、返品数、純売上数）を標準出力またはログに出力し、正しく計算されていることを確認できるようにすること。
- **境界値テスト**: 
    - 純売上がちょうど 0 の商品が抽出されるか。
    - 純売上が正の商品が除外されるか。
    - 在庫表にない商品が（売上が0以下でも）除外されるか。
- **完了マーカー**: 処理完了時に `[COMPLETED]` という文字列を標準出力に印字し、正常終了したことを明示すること。

## 3. 設計規則

### 3.1 入出力規則
- **入力ファイルは読み取り専用**: `inventory.csv`, `returns.csv`, `sales.csv` を上書き、編集、削除してはならない。
- **成果物の制限**: 指定された `deadstock_report.txt` 以外にファイルを生成してはならない。作業用の一時ファイルを作成した場合は、処理終了前に必ず削除すること。

### 3.2 レポートフォーマット
`deadstock_report.txt` は以下のセクション構成とする。

- **死に筋商品一覧**
  - 商品コードと商品名を一行ずつ列挙する。
  - 例: `P003: 消しゴム`
- **判定理由**
  - 各死に筋商品について、判定根拠を具体的に記述する。
  - 書式: `[商品コード] 純売上数量が [数量] 個であり、0以下であるため`
  - 例: `P003 純売上数量が -0 個であり、0以下であるため`

### 3.3 実装上の注意
- CSVのヘッダー行を適切にスキップすること。
- 商品コードの表記揺れ（大文字・小文字）を吸収して集計すること。
