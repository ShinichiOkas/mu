## 総点検で特定した6欠陥（実装済み）

1. **.ps1 の BOM**: write_file は BOM なし UTF-8、モデルは `powershell -File`（5.1 は
   BOM なしを CP932 と読む）→ 日本語入りスクリプトが ParserError ループ（6〜8分/走）。
   `蝠・刀蜷・` 化けが証拠。.ps1 系のみ BOM 付与で根絶
2. **範囲外 offset の無言**: 37行のファイルに offset=45 → 空文字列。事実を散文で返すよう修正
3. **防ぐ層の貫通＋規範の不達**: read-only 属性は `-Force` 3経路に貫通される（016 の実測不足）。
   ACL（`/inheritance:r /grant <user>:(R)`）は全て止める（テストで実証）。さらに
   execute_command が実行毎に digest 照合し、**破れの瞬間に規範の文面ごと**実行者へ返す。
   guard はタスク境界でも見る
4. **保護の不可視**: 保護一覧を env preamble に宣言＋ L4 が L3 の approve スロット
   （`plan_lint`）で保護入力を file にする単位をコードが拒否
5. **write_scope の計画時強制**: 同 lint が scope 外の単位を拒否。**QA の権限衝突
   （5走継続）がこれで消え、QA は初めて判定書を完成させた**
6. **締切の注入**: `deadline`（guard と同型・呼び出し側注入）を L5/L4 が周・タスク境界で見て、
   時間切れは部分結果つき escalate。外部 kill の観測ゼロを構造的に排除

## 転回点 — 師匠にしか見えないものが、今回も決め手だった

3走目に入りかけたとき、師匠が止めた:

> 失敗が続いてトライアンドエラーの状態になってしまっている。ここで一度冷静にコードを見て
> 問題点を論理的に洗い出してほしい。

洗い出しの結果は「仮説1件の修正」ではなく**独立した6欠陥**であり、うち2件（BOM・締切）は
それまでの仮説（保護の穴）と無関係だった。1件ずつ直して再走するトライアンドエラーでは
**最低でもあと3〜4走**を要した計算になる。師匠の言葉:

> 納得した。これは僕には発見できない問題だ。１，２，３，が本質で４，５，６が保護だね。
> 規模も小さいし全部実装しよう

役割の非対称が両方向で確認された: コードの考古学（ログ510行×コード4本の突き合わせ）は
エージェントにしかできず、**プロセスの病理（ドリフト）の検出と停止判断は師匠にしか
できなかった**。エージェントは自分のループを内側から見られない。
