## 主題 — 「制限が無い」とは何だったか

師匠の指示は「扱うファイルサイズに制限が無いように拡張」。AI はこれを
**上限の撤廃ではなく「窓を動かせるようにする」**と読み替えた。振り返りで「思っていた通りです」。

既定窓（`_MAX_OUTPUT` = 4000 文字）は LLM 文脈の防衛として**残したまま**、
要件を「**見えない部分が残らないこと**（到達可能性）」の側に置いた。無制限化の実体は3点セット:

1. **窓** — `offset`（読み飛ばす行数・0 始まり）/ `limit`（最大行数）
2. **位置指定子** — `facts.next_offset`（続きが無いときは `None`）
3. **続きの案内** — 切り詰めたときだけ、呼び直し方を出力そのものに書く（散文と facts の両方）

## 成果（`tools.py` 204 → 315 行）

| ツール | 変更 |
|---|---|
| `read_file(path, offset=0, limit=None)` | 行単位の窓。`read_text()` を廃し**行のストリーム読み**へ（窓の外はメモリに載らない）。総行数だけは最後まで数える |
| `write_file(path, content, mode=)` | `mode="append"` で末尾追加。保護ファイルは mode に依らず拒否（追記も内容改変）。未知の mode は**書かずにエラー＋正しい値を案内** |
| `edit_file` | `old` 不在時のエラーに「末尾追加なら `write_file(mode="append")`」を追記（置換と追加は同居させない） |
| `execute_command` | 切り詰め時のみ全文を一時ファイルへ保存しパスを案内。続きは**既存の `read_file` で辿る**（新機構なし） |
| `list_dir(path, offset=0, limit=None)` | 同じ窓・同じ語彙 |

共通部は純粋関数 `_take_window(lines, offset, limit) -> (shown, total, next_offset)` に集約
（イテレータを受けるので、ファイルハンドルからも `iterdir()` からも使える。CI で決定的にテストできる）。

### 設計上の分岐点（コードにコメントで残した）

- **窓の最小単位（行）は割らない。** 割ると `offset`（行番号）で続きを指せず、辿る手段が消える。
  よって窓より長い1行は丸ごと返す（返る量は最大 `窓＋最長行`）。実測文字数を facts に出して観測可能にした
- **空窓で同じ offset を返さない**（`next_offset = None`）。堂々巡りの防止
- **`facts.bytes` の意味は据え置き**（ディスク実体）、追記分は `appended` を新設。
  既存の検証者（L2/L3）が静かに壊れない → 既存テストは1件も落ちなかった
- モデルは `offset="200"` と文字列で渡しうるので `_as_int` で落とす。ただし**破壊を伴う引数
  （`mode`）は緩めない**——未知の値は実行せずエラーにする
