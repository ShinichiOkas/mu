役割定義書の規範文（プロンプト）は、**観測済みの失敗クラス**の再発防止には効く。
しかし「出典の多様性」「網羅度」「独立性」のような**量的性質**は、規範文があっても
走ごとに振れ、保証にならない。量はテキストでなく**構造**——仕様の操作化された基準・
権限・コード側の決定論検査——に置く。

**Why:** mu 026 の research 実走4走（runs/2026-08-11-026）。個別失敗への規範文は効いた
（URL 転記エラー・未取得 URL 引用は対策後に再発ゼロ）。しかし「1つのソースに全主張を
依存させない」の規範があってもユニーク出典は r2: 7本 → r3: 12本 → r4: **1本**と振れ、
r4 では fetch 18回（公式ドキュメント含む）しながら報告書の出典が単一ブログに収束した。
∀（主張ごとに出典）は同一 URL の使い回しで形式充足する——**量化子を保存しても量は出ない**。
同型の先例: 「実装しない」の規範が確率的にしか効かず権限コードで守った 007 B1、
L3 の自作検査を正準検査（コード供給）に替えた 019。師匠の診断（026 振り返り原文）:
「やはり情報の範囲や振れ幅の大きいものの品質コントロールは難しい」。

**How to apply:**

- 規範文を書いてよいのは**個別の失敗クラスの再発防止**（どう振る舞うか）。
  **量・網羅性・独立性**（どれだけやるか）を規範文で守ろうとしない。
- 量的性質は PdM の仕様で**操作化した基準**にする（例: 「ユニーク出典 N 本以上」
  「比較対象ごとに独立の出典」——数えられる形）か、コード・権限の床に置く。
- 検証者が表象しか見られない性質（出典 URL は貼れるが「読んだか」は見えない）は、
  照合可能な実体（fetch 履歴との突き合わせ等）を検査側に与える構造を考える。
- 規範文の追加で足りているかは**複数走の振れ幅**で判断する。1走の成功は保証ではない。
