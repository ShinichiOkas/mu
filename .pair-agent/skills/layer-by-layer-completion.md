mu の開発は **一つのレイヤを完成させてから次のレイヤへ進む**。複数の層を同時並行で半端に作らない。作る向きは **内側（最も非自律）→ 外側（より自律的）**。

**Why:** 師匠の明示宣言（2026-07-02）。「今回の進め方ではレイヤを一つずつ完成させる方法をとる」。mu の中核モデルが「自律性の層」であり、内側の非自律な核を固めてから自律性を一枚ずつ外へ重ねる、という設計思想と一体。

**How to apply:**

- いま対象の層（現在は L0）が完成するまで、外側の層の実装に着手しない。
- 各層は「概念 → 仕様 → （実装 → 動作確認）」まで完成させてから次へ。当面の成果物は概念仕様が主なので、この段階の「完成」は仕様の確定を指す。
- 外側の層は README 上でスケッチ・方向づけに留め、確定は担当の順番が来てから行う。
- 関連: 合意ドキュメント `.pair-agent/agreements/001-mu-concept-and-l0.md`
