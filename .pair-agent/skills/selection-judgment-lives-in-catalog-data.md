「候補の中から選ぶ」型の判断（パッケージ選択・振り分け・ルーティング）を LLM に任せるとき、
品質を決めるのは判断プロンプトの精緻さではなく、**候補の素性データの質**である。
判断の座を新設するときは、判断文を膨らませる前に材料（データ欄）を整える。

**Why:** mu 028。パッケージ自動選択は初版 director.md（職掌＋記録済み規律のみ・調整ゼロ）で
選択精度 18/18（適合なしの正直な申告 3/3 含む）だった。効いたのはカタログ
（manifest.json の description）——026/027 の実走ループの産物として各パッケージの素性が
正確だったこと。師匠も「苦戦するかと思ったが意外と精度よくできた」（事前予想との差が
このスキルの根拠）。対照的に、規範文で挙動を制御する試みは確率的にしか効かない
（[[quantities-need-structure-not-prose]]）——選択では知識をデータに寄せた構図が最初から機能した。

**How to apply:**

- 選択・振り分けの判断を新設するときは、まず候補の素性欄（description 等）を
  **実走・実測に接地した記述**で整える。判断文は職掌＋境界規律（無理に合わせない・
  適合なしは申告する）の最小から始める。
- 選択の失敗を観測したら、判断文より先に**素性データの側**を疑う（説明が古い・曖昧・
  実態とずれていないか）。
- 標本1（mu 028）の仮説。反例（データが良くても判断文の強化が要ったケース）が出たら改訂。
