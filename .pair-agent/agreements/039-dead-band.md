# 合意 039 — 不感帯（遊び・ヒステリシス）を設計して系を安定させる

status: deliberating（v1 起草。師匠の承認待ち）
created: 2026-08-14

## 背景 — 師匠のビジョンが指した本丸

> 一致させ続けよのイメージが明瞭じゃないので、常に微変更を伴って振動するようなイメージを
> 持っていた。なのでNo－OPの判断はないんじゃないかという予想は当たった。なぜなら振動を
> 避けるためには「このくらいならOK」という遊びやヒステリシスのようなものが必要だから。

no-op は5走連続で不発（032・034・037・038）。原因は規律でも観測の射程でもなく、
**停止条件を幅ゼロで書いていたこと**——閾値ゼロのオンオフ制御はチャタリングする。
実測も振動している（032: 891→3,367→1,646→1,923字 / 038: 保存 62%→100%→0%）。

**目的は「no-op を出させること」ではなく、系を安定させること。** no-op はその結果である。

## まず、既に在るものを数える（[[ask-existing-structure-before-adding-mechanism]]）

| 要る部品 | 既に在るか |
|---|---|
| 観測を1走として回す構造 | **在る**——L2（ゴールを与えて道具で完遂させる） |
| 検査器を書く能力 | **在る**——038 R2 で mu が**頼まれずに** `verify_readme.py` / `.ps1` を書いた |
| ファイルで状態を持つ流儀 | **在る**——L3 のファイル・グラウンディング／tray／037 の baseline 指紋 |
| 「やらない」で終わる契約 | **在る**——034 の `no_action` / `_stop_satisfied`（ただし**二値**） |
| 判定を実体に接地させる床 | **在る**——034（空証拠は False・安全側は進める・根拠を SPEC.md に残す） |
| **量**（閾値を当てられるスカラー） | **無い**——assess は satisfied の二値だけ |
| **閾値**（幅・ヒステリシス） | **無い** |
| **前周の測定値** | **無い**——毎周ゼロから読み直す（035 §6-3 で設計だけ済み） |

**足りないのは3つだけ**である。層を1枚足す話ではない。

## 設計の骨格（案）

```
責務 ──→ ① 検査器を用意する（初回のみ。以後は作業空間に在るものを再利用）
          ↓
       ② 検査器を走らせて **数値** を得る（コードが実行した事実。LLM に数えさせない）
          ↓
       ③ 前回の数値をファイルから読む（走を跨ぐ記憶。エージェントの状態にはしない）
          ↓
       ④ **不感帯**: 数値が「動き出す閾値」未満なら → no_action で終わる
                     超えていれば → 目的を生成して従来どおり L5 へ
          ↓
       ⑤ 作用のあと再測定し、**「止まる閾値」**を下回るまで回す（ヒステリシス）
```

**核心は ② である。** 不感帯は**再現性のある観測の上にしか置けない**——毎周違うやり方で
測った量に閾値を当てても、揺れているのは対象ではなく物差しになる。
032 §6 の結論「一致の機械検査には両側を突き合わせる検査器が要り、それは基準ではなく
**成果物**として要求しなければならない」が、ここで効いてくる。

## 実行中に採る判断（AI の判断・事後確認対象）

- 検査器の置き場と名前（作業空間の規約）
- 測定結果ファイルの形式（JSON の欄名）

## 決めたこと（2026-08-14・師匠）

| 論点 | 決定 | 理由 |
|---|---|---|
| **量の出所** | **mu が作った検査器の出力** | コードが実行した事実なので再現性がある。揺れる量に閾値を当てても振動は止まらない（033 B3: 生成に同梱した判断は生成に引かれる） |
| **幅の非対称** | **軸ごとに変える。誤りは幅ゼロ** | 誤りは害が大きく、しかも実測で5走中0件——幅ゼロでも振動の原因にならない |
| **閾値の在り処** | **責務文（人間が書く）** | 「このくらいならOK」は**任せる側の宣言**であり、ドメインごとに違う。コードは幅を知らず、比較だけを決定論で行う |

### 責務文 v3（案）— 閾値を人間が書く

> この作業ディレクトリのリポジトリについて、README.md を実装と一致させ続けよ。実装が正であり、
> README.md の側を実装に合わせる（実装ファイルは変更しない）。
>
> **まず現状を測れ。** `measure.json` に前回の測定結果があり、検査器があるならそれで測り直せ。
> 無ければ検査器を作れ。測った結果は `measure.json` に残せ。
>
> README.md は、実装を構成するファイル・役割・それらの数について漏れなく述べ、かつ既に
> 述べている事柄を減らさないこと。
>
> **直す基準はこうである:**
> - **実装と食い違う記述（誤り）は、1件でも直せ。**
> - **述べていない事柄（不足）が2件以下なら、直さなくてよい。3件以上あるなら直し、
>   1件以下になるまで直せ。**
> - **前回まで述べていた正しい記述は落とすな。**
>
> すでに誤りが無く、不足も2件以下なら、何も変更しなくてよい。

不足の「3件以上で動き、1件以下で止まる」が**ヒステリシス**である。2件は現状維持——
ここが遊びであり、閾値の境界で振動しないための幅である。

**前周の状態は `measure.json` が持つ**（エージェントの状態にしない）。
検査器そのものも作業空間に残るので、**同じ物差しで測り続けられる**——量が比較可能になる。

## スコープ（階段で測る）

師匠の流儀「議論ではなく測定で決める」に従い、**安い側から測る**。

1. **A — 責務文 v3 だけ（コード変更ゼロ）**: 閾値・観測の順序・測定結果の残し方を文言に書き、
   `R0,R1,R2,R3` を1セット走らせる。**mu は自力で「測る → 判定する → 必要なら直す」を
   編めるか**を見る。既存構造で足りるならここで終わる
2. **B — 責務の座（A で足りなかった場合のみ）**: 観測1走 → 測定結果を読む → 不感帯で判定 →
   超えていれば目的を生成して L5 へ、という薄いループをコードにする。判断は持たない
   （比較は決定論・目的の文言は責務文から）
3. **C — 実証**: 4周で振動が止まったかを3軸で測る

## 完了条件（案）— 「安定した」を測る

4周（R0,R1,R2,R3）を同じ物差しで走らせ:

- **R0 / R3 で `no_action` が出る**（一致も網羅も満たしている周で動かない）
- **嘘が 0 件を維持**（不感帯は嘘を見逃す言い訳にならない）
- **保存率が周を跨いで単調に落ちない**（振動が止まった＝系が安定した、の実測）
- 通常の目的（作る仕事）が誤って no_action に落ちない（回帰）
