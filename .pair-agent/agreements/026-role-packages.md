「リサーチ用の役割定義を作る」の合流点。025 で先送りした「マニフェスト欄設計・ファイル移動」が
今回の主題になる。

## 協議で決まったこと（2026-08-11・師匠の選択）

1. **範囲 = 器＋研究1本実走**: パッケージの器＋現行セットの coding パッケージ化＋
   調査レポートパッケージを実走の失敗観測で書いて検証。研究開発・秘書業務・書籍執筆は
   マニフェストに枠（名前と説明）だけ置き、次スプリント以降に1ドメインずつ。
   承認済みスキル「役割文は想像で一般化せず実走の失敗観測から書く」に準拠。
2. **切り替え = 手動のみ（L6）**: 起動時指定で人がパッケージを選ぶ。L5 自動選択の内在化は
   検証済み2セットが揃った後の候補（vision/024 の方針どおり）。
3. **構成 = 自己完結型**: 各パッケージが4ポジション（pdm/pjm/qa/implementer）＋ドメイン役割の
   全部を持つ。新ドメインは coding の調整済み文のコピーから出発し、そのドメインの失敗で調整する。
   重複は許容（ドメイン間の干渉ゼロを優先。[[same-shape-different-domain-no-merge]] と整合）。

   走行記録を runs/ に残す。

## 実行中に採る判断（AI の判断。事後確認対象）

- **レイアウト**: `roles/<package>/` 方式（`roles/coding/`, `roles/research/`, …）。
  `load_roles` のグロブは非再帰なので既存機構と衝突しない。
- **マニフェスト**: 各パッケージ直下の `manifest.json`（stdlib json・`*.md` グロブと衝突しない）。
  欄は `name` / `description` / `status`（verified | draft | planned）。
  coding の初期値は verified（019〜025 の実走群が根拠）、research は draft で出発し、
  **verified への昇格は師匠の承認事項**（スキル成熟度と同型: draft → 実走 → 師匠が確定）。
- **切替面は環境変数 `MU_ROLES_DIR`**（probe の既存引数体系は変えない）。
  ※協議時は `MU_ROLES` としたが、着手時に probe_hard.py が既に `MU_ROLES_DIR` を
  読んでいる（008 の対照走で使用実績）ことを発見——新変数を増やさず既存名を
  カンマ区切り合成に拡張する（2026-08-11 実行中の調整）。
- **研究のドメイン役割は researcher 1本から**。多役割化（編集者式）はドメインの失敗が
  要求してから足す。
- **pjm 人選指針（architect / design.md 前提）は初回走行までコピーのまま**。
  誤誘導の観測が先、修正は観測後（LONGTERM_TODO の「見る」の指示どおり）。
