# 合意 037 — 035/036 で見つかった穴を塞ぐ

status: executing（2026-08-14 師匠承認。A は階段を踏まず**いきなり構造**／E は5走＝師匠の選択）
created: 2026-08-14

## 背景 — 実測で見つかった穴は4つ

| # | 穴 | 標本 | いまの姿 |
|---|---|---|---|
| **A** | **保守対象が tray に入る保証が無い** | 035（陰・2走）／036 maintain（陽・2走） | `needs` に書かれたかどうかは PjM の1判断。外れると原本が手元に無く、**書き手は作り直すしかない**（README 47KB → 5.5%） |
| **B** | **needs ゲートは「未宣言」に無力** | 035（2走） | 名前を間違えて弾かれた PjM は、宣言を**直さず捨てた**。罰を避ける最も安い道が「宣言をやめる」 |
| **C** | **修理が契約を壊す／場所に縛られる** | 036 repro（2走とも） | 絶対パスの埋め込み（`S:/tmp/...`）と列名の改名（`total`→`total_amount`）。QA は全項目 PASS を出した＝**書いていないことは誰も見ていない** |
| **D** | **回帰の基準を後から作る** | 036 compat-r1 | 変更後の実装で golden を作り、以後「既定の出力が golden と違う」と自分を責め続けて予算切れ |

A は**陰陽そろった2標本**である。同じ層・同じモデルで、トレイに原本があるかどうかだけで
結果が反転した（035: 5.5% に破壊 ↔ 036: 9,169→9,649 バイトで無損失）。

## 設計方針 — 穴ごとに解く高さを変える

[[contracts-not-knowledge-define-outcome-kinds]]（契約に無いものは知識では作れない）と
032 の階段（接地 → 自力 → skill → 構造）に従う。

### A — 構造で解く（コードの決定論）

> **更新の仕事は「入力＝出力」の形をしている。**

いまの `_prepare`（`mu/l4.py`）は `needs` だけを tray に写す。ここに1行の決定論を足す:

```
tray を用意 → 残骸を捨てる → needs を写す
                            → ★ t["file"] が共有空間に実在するなら、それも写す
```

**判断は要らない。** 宣言出力が既にあるなら、そのタスクは定義上「更新」であり、
原本は入力である。合意032 の接地修理（目的が名指したファイルを先頭に置く）と同じ
「**並び順・写し込みという構造で守る**」型。上限も語彙も増えない。

**副作用への床**: 原本を先に写すと、実装者が何もしなくても `publish` の
「宣言した出力が作業ディレクトリに無い」検査を通ってしまう（＝**静かな失敗**が生まれる）。
よって**写した原本のダイジェストを覚え、発行時に同一なら「未変更で発行」を log とタスク結果に残す**。
判定は上（QA / PjM）に委ねる——034 の no-op と同じ思想で、**握り潰せない証跡**にする。

### B — 接地の修理で解く（構造・安価）

ゲートの失敗文に**候補**を添える。`l0.py` が無い ⇒ 同名の実ファイル `mu/l0.py` を見つけて
「近い名前: mu/l0.py」と書く。宣言を捨てるより直すほうが安くなる。
（合意032 で接地を直した途端に mu が自力で観測タスクを編んだのと同じ形。）

### C・D — skill で解く（実観測に基づく規範のみ）

[[prompt-norms-are-countermeasures-not-generalities]] に従い、**036 で実際に観測した失敗だけ**を書く。

| skill | 宛先 | 中身 | 標本 |
|---|---|---|---|
| `no-absolute-paths-in-deliverables` | implementer | 成果物のコードに絶対パスを埋めない。入出力は作業ディレクトリからの相対で書く | repro-r1 |
| `repair-must-not-change-the-contract` | implementer | 修理・拡張では既存の出力契約（ファイル名・列名・書式・関数の署名）を変えない | repro-r2 / compat-r1 の列 |
| `baseline-before-the-change` | implementer | 回帰の基準（golden）は**変更を加える前に**取る。変更後に取った基準は基準ではない | compat-r1 |

## スコープ（フェーズ＝コミット単位）

1. **A — 機構（TDD）**: `_prepare` の写し込み＋未変更の可視化。ユニットは
   （既存出力あり→写る／無し→従来どおり／未変更発行→記録が残る／絶対パス出力→従来どおり）
2. **B — 機構（TDD）**: ゲート失敗文の候補提示。ユニット（候補あり／無し／複数）
3. **C/D — skill 3件**: `skills/` に追加。**プロンプト面を触るので coding スモーク必須**
   （confirmed スキル [[smoke-test-before-close-after-prompt-changes]]）
4. **E — 実証（同じ物差しで前後比較）**:
   - 035 の R1/R2 を再走（**A の効果**。implementer の tray に README.md が入るか）
   - 036 の `repro` ×1・`compat` ×1（**C/D の効果**。絶対パス・列改名・golden 汚染が消えるか）
   - `maintain` ×1（**回帰**。既に 16/16 が出ている題材を壊していないこと）
