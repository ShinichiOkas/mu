# 合意 040 — 依存宣言（Makefile 形式）と決定性の解決

status: executing（2026-08-15 師匠承認。「形式だけ借りる」「進めてください」）
created: 2026-08-15

## 背景 — 師匠の設計

> 依存性記述があった場合、その依存性を紐解いて何を変更すべきかは決定性のツールで判断し、
> その結果に従ってLLMが動く構造の方が確実で柔軟であるということですよ。
> **Makefile形式は依存を決めるが手順を決めないから。**
> Makefile形式はほぼあらゆるLLMが熟知しているはず。であるなら依存性を表現する方法として
> Makefile形式を求めてもLLMは記述でき、Makefileがある場合は決定性の依存処理ツールが
> すべきアクションを特定するという柔軟なハーネスができるのでは？

**判断の難易度を、形式の選択で下げる**のが核心である:

| mu に求めていた判断 | 難易度 | 実測 |
|---|---|---|
| 「README は実装と一致しているか」 | 高い——検査器を書かせると盲点が入る | 040 過剰報告11件／042 盲点で0件／7走とも失敗 |
| 「README は何に依存するか」 | 低い——1行の宣言。**人間が一目でレビューできる** | LLM が最も熟知した形式 |

そして **Makefile 形式は依存を決めて手順を決めない**——だから汎用性を削らずに確実性だけ足せる
（師匠が懸念した「がちがちにすると汎用性が損なわれる」への構造的な答え）。

## 決めたこと

- **形式は Makefile を借りる。`make` は呼ばない。** 理由: Windows に make が無い／
  recipe がシェル前提で「LLM タスク」を書けない／陳腐化判定はハッシュ比較で足りる
  （`mu/workspace.py` の `digest()` が既にある）。**形式の恩恵（LLM の熟知・人間の可読性）だけを取る**
- **記述は LLM でも人間でもよい。決定性は解決器にある。** 北極星は縮まない
  ——mu が決めるものが「一致しているかの判定」から「何が何に依存するか」に移るだけ

## 設計

### 1. `mu/deps.py`（facility・LLM を持たない）

```
DEPS.mk                       .mu-stamp.json
README.md: mu/*.py roles/*.md      {"README.md": {"mu/l0.py": "<hash>", ...}}
	README を依存先に合わせて更新する
```

- `parse(text)` — target / prereqs / recipe（TAB 行）に分解。`#` はコメント
- `expand(rules, root)` — glob を実ファイルに展開
- `stale(rules, root, stamp)` — **陳腐化したターゲットの一覧**を返す（判断ゼロ）
- `stamp(rules, root)` — いまの前提のハッシュ表を作る

**陳腐化の規則**（すべて決定性）:

| 条件 | 陳腐化 | 捕まえるドリフト |
|---|---|---|
| ターゲットが存在しない | ✓ | 新規作成 |
| stamp にターゲットの記録が無い | ✓（保守的） | 初回 |
| 前提のハッシュが stamp と違う | ✓ | 内容の変更 |
| stamp にあった前提が消えている | ✓ | **削除**（032 R2 型） |
| glob に新しく合致する前提が増えた | ✓ | **追加**（032 R1 型） |

**失敗の向きは安全側**——依存を広く書きすぎれば余計に走るだけ（偽陽性）。
書き漏らせば見逃すが、**宣言は1行なので人間が読んで気づける**（450行の検査器はレビューできない）。

### 2. L5 への配線（`_assess` の手前）

```
接地（inputs）を採る
  ↓
★ DEPS.mk があるか？
   無い → 従来どおり（assess → specify → L4）
   ある → **決定性の解決**
            陳腐化ゼロ → no_action で終了（**判断を回さない**）
            陳腐化あり → その一覧を目的に添えて従来の経路へ
  ↓
assess（LLM）→ specify → L4
```

**`no_action` が判断から規則になる。** 034 で作った終端はそのまま使う——契約は変えない。

- 成功（`achieved`）で終わった走だけ **stamp を更新する**。失敗した走で更新すると、
  直っていないものを「新しい」と記録してしまう
- 解決の結果は実況とイベントに出す（`deps_stale` / `deps_uptodate`）——
  「なぜ動いたか／動かなかったか」が握り潰せない証跡になる

### 3. 責務文 v5

検査器を作らせる文（v4 の143字）を**依存宣言に置き換える**。
「一致しているか測れ」ではなく「**何に依存するかを DEPS.mk に書け**」。
